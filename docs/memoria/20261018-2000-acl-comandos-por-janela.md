# ACL do Tauri v2: comandos do app por janela

tipo: armadilha
origem: task #807 · claude · 2026-10-18

- Sem `AppManifest::commands` no `build.rs`, todo comando do `generate_handler!` vale para qualquer janela (o HUD também podia chamar `set_config`, `download_model`...). Com a lista declarada, cada comando só passa na janela cuja capability tem `allow-<comando>` (nome em kebab-case: `list_models` → `allow-list-models`).
- O `tauri-build` gera `src-tauri/permissions/autogenerated/*.toml` a cada build: está no `.gitignore`, não versione.
- Permissão inexistente numa capability quebra o `cargo build` (o `tauri-build` valida), então erro de grafia aparece já nos checks.
- O HUD só usa `listen` de `@tauri-apps/api/event`: `core:event:allow-listen` + `core:event:allow-unlisten` bastam. Se o HUD passar a usar outra API (janela, app), acrescente a permissão em `capabilities/hud.json` e no teste `crates/pointspeak-core/tests/capabilities.rs`.
- `Path::is_absolute` depende do SO do host: para validar caminho de outro SO em teste (Windows no runner Linux), compare a grafia (`C:\`, `\\`) como em `onnx_runtime::is_absolute`.
